# Open-Asset Research & Integration Plan — Story Mode

> Status: **Phase 1–3 complete (research + plan). Phase 4 (implementation) gated on the design decisions in §3.3.**
> Method: five parallel research agents — asset inventory, runtime loading architecture, story-mode presentation audit, open-image-source survey, open-audio-source survey. All external URLs in this doc were `curl`-verified reachable from the build sandbox.

---

## 0. Executive summary

The battle layer is already richly served (986 animated front sprites incl. Mega/Gmax, 1,192 cries, 378 trainers, a full move-SFX library). **The deficit is entirely in story-mode presentation:** most high-drama beats render on flat color, music is a single ambient pool shared across the whole game, and several shipped assets are dead weight.

The four highest-leverage moves, ranked by impact ÷ effort:

1. **Wire up the 4 dead `Theme*.mp3` into a scene-mood music map** — battle/leader/boss/victory themes, *zero downloads, zero licensing exposure*. The single biggest free win.
2. **Real backgrounds behind the flat high-drama screens** (starter pick, wild/Safari, the Caged God boss, Mystery reveal, Crucible/Frontier).
3. **A proper "VS" battle-intro** for leaders/rivals/champion/boss (uses sprites we already ship).
4. **Complete local back-sprite coverage** — today every ordinary player Pokémon's back sprite is fetched *remotely from Showdown on every battle*.

**Decisions needed before Phase 4** (see §3.3): scene-background **style**, **audio** posture, **back-sprite** vendoring vs remote fallback, and **repo-size** posture. These set visual/audio direction, so per the brief they are yours to call.

### 1.2 Runtime architecture (how assets resolve)

- **Sprites** — `getSprite()` (battle.html:13299) is local-first via an autogenerated `LOCAL_SPRITE_MANIFEST`; a miss returns a **remote Showdown URL outright**. `handleSpriteError()` (13322) then walks a 7-step remote chain across `play.pokemonshowdown.com` and `raw.githubusercontent.com/PokeAPI`. There is **no bundled local placeholder**. The player's active Pokémon renders **back-facing** (`#player-sprite[data-back]`, 9586) — so every ordinary species' back sprite is a remote fetch each battle.
- **Cries** — local `music/cries/{id}.mp3`, Showdown fallback (11844).
- **BGM** — `AudioSystem` (11483) rotates **3** `background/*.mp3` at random, gapless, continuous. **No area/scene/battle mapping; story and battle share the same pool.** `music/themes/*` is unused.
- **Move SFX** — `MOVE_SFX_MAP` (move-sfx-map.js) → `music/battle_anims/PRSFX- *.wav`, type-sound fallback `music/moves/<type>.mp3`. `move-anim-map.js` is *programmatic* animation params, not files.
- **Battle bg** — `getBattleBgUrl(terrain, layout)` (9685): terrain × orientation, 5 terrains only, no fallback.
- **Story bg** — **manifest-driven**: `fetch('sprites/story/backgrounds/manifest.json')` with an inline `DEFAULT_STORY_BG_MANIFEST` fallback (33976). Swapping art = drop file + edit manifest (+ keep default in sync).
- **Story icons** — hardcoded `<img>` with `?v=` cache-bust; `onerror` hides.
- **No central asset-base constant**; all inline relative paths.

### 2.2 Audio

- **No clean, openly-licensed, Pokémon-specific BGM exists on any GitHub-reachable source.** Official OST is copyrighted everywhere.
- **Tuxemon/Tuxemon** (GPL game) vendors **CC-BY 3.0 / CC0** JRPG-style town/route/battle/boss tracks — raw-reachable (verified 200). The one openly-licensed BGM option, but it is *generic JRPG*, not Pokémon.
- **PokeAPI/cries** reachable but copyrighted + format-mismatched (`{dexID}.ogg` vs our `{name}.mp3`); useful only as a gap-filler.

### 2.3 Licensing reality (honest)

All underlying Pokémon imagery/audio is **© Nintendo / The Pokémon Company / Creatures / GAME FREAK.** The repo "licenses" (CC0/MIT) cover compilations, code, and data maps — not the IP of official art. PMDCollab additionally licenses its *original fan-drawn* art (with attribution). This project already stands entirely on fan-ripped Showdown assets, so adding more is consistent footing **for a non-commercial fan game** — but none of it should be represented as officially licensed. **Plan:** add an `ATTRIBUTION.md` + per-source license files (extending the existing `pokesprite/UPSTREAM_LICENSE.md` precedent) and an explicit non-commercial fan-project note.

### 3.2 Integration approach (best practice)

- **Local-first, remote-fallback already exists** — extend it, never break it. Vendoring buys offline support + removes per-battle remote fetches; the remote chain stays as the safety net.
- **Reuse the existing pipeline** (`download → optimize → manifest → verify`). New fetchers (`download-back-sprites.mjs`, `download-item-icons.mjs`, `download-pmd-portraits.mjs`) follow the same idempotent, `--force`/`--only`, pLimit(8) shape as `download-mega-gmax-sprites.mjs`. Pin to commit SHAs for reproducibility.
- **Folders align with existing structure** — extend `gen5ani-back*`, `sprites/items`; add `sprites/portraits/` (PMD) and grow `sprites/story/backgrounds/` (manifest-driven, keep `DEFAULT_STORY_BG_MANIFEST` in sync). Music to `music/themes` (already present) and/or `music/areas/`.
- **Fallbacks on every new reference** — `<img onerror>` to remote-or-hide (match existing); background layers degrade to gradient; new manifest entries keep the inline default synced.
- **Performance** — `loading="lazy" decoding="async"`, preload only above-the-fold, `gifsicle -O3 --lossy` on GIFs, re-encode oversized audio, respect the LRU(300) preload cap.
- **No duplicate assets** — dedupe the loose `sprites/*.png` copies; one source of truth per asset.
- **Attribution** — `ATTRIBUTION.md` + per-source license files; honest non-commercial fan-project note.

### 3.3 Design decisions required (your call — see the questions accompanying this plan)

- **Q1 — Scene-background style/source.** Pixel-rip (pokeemerald) vs hand-authored CSS/SVG vs AI-generated (extend Gemini) vs hybrid. *There is no big open DB of ready-made Pokémon location backdrops* — the major DBs are sprites, not scenery — so this is a genuine style-vs-effort-vs-licensing fork.
- **Q2 — Audio posture.** Free reuse of the 4 dead themes (zero licensing) vs also vendoring Tuxemon CC-BY tracks (more variety, non-Pokémon, needs credit).
- **Q3 — Back-sprite vendoring vs remote fallback.** Offline + per-battle perf vs repo size (no LFS).
- **Q4 — Repo-size posture.** Aggressively optimize + dedupe + re-encode the 206 MB music as part of this work, add-only, or migrate to Git LFS.

All four design decisions were answered and implemented. Decisions: **Q1** scene art = gen3 pixel rips; **Q2** audio = reuse + Tuxemon CC; **Q3** = vendor full back-sprite coverage; **Q4** = optimize/dedupe/re-encode.

| **Q4 — Hygiene** | Re-encoded `background{1,2}.mp3` 172→128 kbps (−39 MB; background3 left as-is, already ~90 kbps). Deleted 5 unused loose backgrounds (−13 MB). Added `ATTRIBUTION.md`. | `chore(assets): re-encode BGM + drop loose dupes + attribution` |
| **Q2 — Audio** | Battle-theme override layer in `AudioSystem`; wired the 4 dead `Theme*.mp3` to moods (trainer/leader/rival/elite) + 2 CC-BY Tuxemon tracks (boss + victory). Field BGM ducks/restores. | `feat(audio): scene-mood battle themes` |
| **Q1 — Backgrounds** | `scripts/build-story-backgrounds.mjs` assembles gen3 map-preview tile-atlas+tilemap into 10 pixel scenes (pure-Node PNG codec). Wired into catch (forest/safari/cave), professor (lab/villain), Crucible (league), Frontier (mansion) via a manifest `scenes` map + `syncStorySceneBackground`. | `feat(story-bg): assemble + wire gen3 pixel backdrops` |

**Net size:** back sprites +92 MB; music −39 MB; dedupe −13 MB; gen3 + Tuxemon +~2.5 MB → ~+42 MB working tree. (The 128 kbps music saving was smaller than first estimated because the loops were 172 kbps, just very long — not 320 kbps.)

**Honest correction recorded during build:** Q1's gen3 rips are *not* drop-in images — gen3 scenery is a tile-atlas + `.bin` tilemap, so an assembler was built (re-confirmed with the user, who approved "assembler + author the gaps"; in practice gen3 interiors covered the gaps, so no off-style CSS was needed).

**Not in this pass (available next steps, lower impact / new design calls):** a "VS" trainer-intro *visual* (music shipped; the splash screen is a separate visual-direction call), item-icon completeness (8.6%→full, a clean coverage win like back sprites), facility NPC portraits, animated egg hatch, per-city distinct backdrops.

**Validation:** each slice verified — manifest parse-check, jsdom boot of the full monolith, integration test (`catch-system` 4/4), `ffprobe` duration checks, and direct image review of every gen3 scene. Live in-browser screenshots weren't possible (Playwright's chromium isn't installed and its CDN is outside the GitHub-only network).
