# App, settings, saves and delivery

Use this reference for title and entry flows, shared navigation, preferences, room forms, local data, installation and release changes. Runtime identifiers can be searched even when source line numbers move. For a full interface change, follow the linked feature checks as well as the shared controls in this document.

### App home scores

Gauntlet scores opens a shared modal with loading, empty and service unavailable messages. It reads the first 100 entries in descending rounds order and renders rank, trainer name, rounds and optional party sprites. The scroll region can receive keyboard focus when scores are present. Tab stays in the dialog. Close, Escape and browser Back restore focus to the opener. Sprite art loads on demand. The end-of-run opt-in submission is a separate write with success or unavailable feedback. Check a closed dialog reopening while a request settles and retry when the service becomes available. ## Shared dialogs

- **Alerts and confirmation.** `openModal` and `_registerAppDialog` capture the opener, mark the underlying surface inert, record Back history, place focus inside, and restore it on close. The alert queues messages. Confirmation resolves cancellation on Escape, Close, Back or route change so an unanswered prompt cannot block a transaction. Pending room operations can restrict dismissal. Check children over Settings and dynamically generated overlays, with focus and scroll restored to the parent.
- **Global navigation and notices.** Screen exit can return to the previous surface, save a checkpoint or require battle/draft confirmation. Check explicit Back, Escape, browser Back, clicking the backdrop where allowed, and reload. The app loading overlay, toast host, optional text tooltips and Story Notifications have different lifetimes. Story’s event history, field hints, campaign choice defaults, timing and cinematics are in the field and world guides.
- **Responsive behavior.** Check the shared frame, viewport insets, portrait and short landscape, keyboard reachability, text zoom, focus restoration after data rerenders, layer order and long dialog scroll. Keep the next action reachable above browser and keyboard bars.

## App save

| Surface or record | Review coverage |
| --- | --- |
| Local storage | `pbs_story_save` stores the active Story slot (schema v28 currently) and `pbs_story_meta` contains career/collection records. `pbs_settings` and `pbs_accessibility` store shared preferences. `pbs_slot_1` through `pbs_slot_3` are optional local slots. Worker shell/media caches, audio position and room display name have separate owners. Read `GameStorage` and `GameUpgrades.makeBackup` to check what is portable. |
| Save and exact turn resume | Auto-save marks durable Story transactions. Save & quit returns to Story menu. Continue shows saved turn on a matching checkpoint. Supported native encounters can resume from a committed turn, including battle state and RNG. Incompatible snapshots can fall back to the frozen encounter checkpoint. Check save during animation, action retry, unresolved choices, malformed or stale snapshot and unchanged opponent on retry. A failed-save result dialog offers Back up now and Retry save. The alert banner clears when the dialog owns recovery, keeping both actions reachable in short landscape. |
| Run information, deletion and diagnostics | Run Info shows journey settings and seed. Manage run → Delete Run confirms removal of the active slot and preserves lifetime collection. Check Cancel, absent and unavailable states, cross-tab changes and the affected records. The Notebook can export a run passport. Trace/detail and raw save export are addressed by the release fixture guidance. |
| Save & recovery | Title entry for save problems and Settings → Data. Shows last save, no-run, unreadable or storage error and Retry saving when eligible. Complete and settings-only backups use V1 JSON. Backups can contain progress, collection, game settings, accessibility preferences and three user slots. Check file picker cancellation and backup preview before applying changes. |
| Local slots, checkpoints and emergency copies | Empty Save here and occupied Replace this slot or Review and load, latest and earlier checkpoints. Preview origin and incoming/current save. Reject unrecognized, malformed, too-large and incompatible files. Preserve raw broken data and review it when eligible. Restore protects against stale review, concurrent writes and partial application, saves a recovery copy and blocks during battles or pending actions. Career merge keeps applicable archival proof. |
| Migration and failure fixtures | Check first save, compatible old, inactive, newer, corrupted, storage denied, quota exceeded and stale concurrent writes. Verify progress, team, inventory, story locks, settings and lifetime records after restore. Confirm settings-only restore preserves the active run. Remove the media pack and verify saves and slots remain. |

## App delivery

| Surface or layer | Review coverage |
| --- | --- |
| Cold boot and readiness | Public title loads small shared storage/CSS and defers battle data, optional audio and bulk art. Selected game flows use the app loading overlay and `prepareGameData`. Core Dex, learnsets, the engine and optional modules load when the flow needs them. Check first action from public title, first draft and battle, first Continue, warm return, missing dependency, partial-load retry and repeated transfers. |
| Install and browser use | The web manifest defines icons, start URL, scope and app display behavior. Settings uses the deferred native prompt where available or offers contextual browser/iOS/macOS instructions. Inspect browser tab, standalone, existing install, denied prompt and unsupported mode. Launch the installed title without a connection after the matching cache has been prepared. |
| Offline play | Settings Data offers Compact (still sprites and short tracks) and Full (animated sprites and longer tracks), pack comparison, estimated new bytes, progress, pause/resume, repair and removal. Both packs include Story. Check initial registration, profile selection, update available, quota failure, interrupted transfer, profile switch, integrity check, ready and offline/error feedback. Install provides a core shell path. Finish a pack for the associated Story media. |
| Update and rollback | Title Check for updates and in-game Data check for new shell or asset data. Worker verifies immutable release files and reuses unchanged objects. During handoff, eligible tabs prepare, block actions and release on the verified transition. Check battle/draft deferral, saved Story boundary, failed handoff cancellation, focus recovery and new version after reload. Test A → B → retained A with incomplete releases and unchanged optional media. |
| Removal and uninstall | Remove offline files with confirmation releases optional data and preserves core shell, saves and preferences. Uninstall via the device or browser and back up before clearing site data. Check usable state after removal and fresh-profile backup import. |
| Packaging and evidence | Regenerate Arena bundles/icons from their changed inputs and the offline manifest when served assets change. Build the allowlisted immutable release graph under `dist/`. The runbook gives authoritative commands, version/digest, baseline and device proof. Measure cold/warm title and first playable turn under matching conditions, transfers during update, cache delta, memory across repeated mode changes, both pack sizes and staged rollback. |
