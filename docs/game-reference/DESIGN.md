# Game rules and design sources

Run `npm run audit:game -- --scope design --json` for the file index for [docs](..) and [design](../../design), together with the live rules and presentation catalogues. Search the JSON by topic or filename. Start with the controlling runtime and shipped rules below. Many older designs and spreadsheets describe the requirements or observations from their original build. Verify their numbers and availability against implementation before using them as current player guidance.

| Domain | Current authority and relevant design |
| --- | --- |
| Campaign structure and unlock pacing | `STORY_EVENTS_RAW`, `FACILITY_DEBUT_CITY`, the Story milestone, grading and tier helpers in [battle.html](../../battle.html), and the [campaign files](../../data/story). Reference the [progression master](../PROGRESSION_CURVE_MASTER.md), [Story flow](../../STORY_MODE_FLOW.md), [campaign guide](../north-road/CAMPAIGN.md), and the authored [timeline](../story-design/story-timeline.csv), [cities](../story-design/story-cities.csv), [power curve](../story-design/story-power-curve.csv), [facility debut](../story-design/story-facility-debut.csv), and [service availability](../story-design/story-service-availability.csv) tables. Tool and service guides record known discrepancies. [Facilities](FACILITIES.md) · [World](WORLD.md) |
| Gold, prizes, costs and economy | In [battle.html](../../battle.html), inspect the timeline reward list, `STORY_BASE_TRAINER_GOLD_MULT`, battle and errand payout, first and repeat claims, loss rules and postgame receipts. For purchase prices, [story-shops.csv](../story-design/story-shops.csv) is the authored input to the [catalog generator](../../scripts/build/generate-shop-catalogs.mjs) and [shipped shop data](../../data/story/shops.json). Service prices can also be computed by their controllers. See [loot rules](../story-design/LOOT_SYSTEM_DECISIONS.md), [item rules](../story-design/ITEM_SYSTEM_OVERHAUL.md), [tunable references](../story-design/story-tunables.csv) and [campaign structure](../story-design/story-core-structure.csv). |
| Player power and build suggestions | [battle.html](../../battle.html) implements Story level, grades, specialty abilities, IV/EV/Experience Share, move legality and tier caps, equipped items and transformations. The [archetype templates](../../data/build-archetypes.json), [move utility data](../../data/competitive-moves.json) and battle data support loadout generation. Review [Dojo and Tutor recommendation design](../DOJO_TUTOR_RECOMMENDER_DESIGN.md), [IV tiers](../story-design/story-iv-tiers.csv), [evolution](../EVOLUTION_FLOW_REBUILD.md), [build diversity](../BUILD_DIVERSITY_MASTER.md) and [generator review](../BUILD_DIVERSITY_TESTING_REVIEW.md). |
| Opponent and wild strength | Follow `TRAINER_DATA`, the Story opponent and wild generation and grade helpers in [battle.html](../../battle.html), battle seed accounting, maps, signature Pokémon, rival history and run settings. The [wild curve](../../design/MASTER_02_wild_curve.csv), [starter curve](../../design/MASTER_03_professor_curve.csv), [trainer scaling](../../design/MASTER_04_enemy_trainer_curve.csv), [role/pool table](../../design/MASTER_05_trainer_types_and_pools.csv), [grade profiles](../../design/MASTER_06_grade_profiles_by_type.csv), [ace rules](../../design/MASTER_07_signature_ace_rules.csv), [rival counter rules](../../design/MASTER_08_rival_counter.csv), and [Tutor/Dojo tables](../../design/MASTER_09_tutor_dojo.csv) give the design lineage. After changing a cap, compare wild, ordinary trainer, rival, signature boss, endgame and player availability at both edges of that gate. |
| Combat formats and retry | Arena format choices and rules live in [competitive](../../competitive), with Classic/Story adapter boundaries and battle completion in [battle.html](../../battle.html). Read [combat](../north-road/COMBAT.md), [save and replay](../north-road/SAVE_AND_REPLAY.md), and [engine test documentation](../../tests/README.md). Test legal input and replacement for the mode, phase, generation and allowed mechanics. |
| Exploration and capture | The shipped [ball rules](../../data/story/ball-math.json), [campaign routes](../../data/story/campaign.json) and Story action handlers govern wild rolls, Safari fees and exits, legendary hunts, capture placement and repeat encounters. See [narration](../story-design/STORY_NARRATION_SYSTEM.md), [opening notes](../story-design/story-intros.csv), [campaign](../north-road/CAMPAIGN.md) and [story immersion studies](../story-design/story-immersion). |
| Interface, art and audio | [Public title and Classic](../../index.html), [home/menu CSS](../../home-menu.css), [shared upgrades](../../game-upgrades.css), [location composition](../../world-location.css), [activity CSS](../../story-activities.css), [Arena CSS](../../competitive/arena.css) and Classic inline styles. Record the exact package for tests of startup, offline assets, save behavior and updates. |

When an update changes a rule, trace the authoring file, generated data, runtime decision, player indicator, AI alternative, save migration if needed, and the tests that assert the boundary. Update the currently used design reference where behavior or instructions have changed. Keep dated observations and superseded specs identifiable by their original context.
